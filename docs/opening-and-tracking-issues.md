# Opening and tracking issues

This repository is the **public place to talk to the Robo Trader team**. Issues are welcome from everyone — users, testers, and anyone evaluating the product.

**Please open issues.** Feedback makes the product better. You are not “bothering” anyone by filing a clear report.

---

## Why open an issue?

| Situation | Open an issue? |
|---|---|
| Something broke or looks wrong | Yes — Bug report |
| You want a feature or UI improvement | Yes — Feature request |
| Docs or the app are confusing | Yes — Bug (docs) or Question |
| You are not sure whether it is a bug | Yes — Question or Bug; we will triage |
| You need help signing up or waiting on approval | Yes — Question |

You do **not** need source code, logs from servers, or engineering access. Describe what you saw and what you expected.

---

## How to open an issue (step by step)

1. Sign in to [GitHub](https://github.com/login) (free account is enough).
2. Open **[New issue](https://github.com/guymaim/robo-trader/issues/new/choose)** for this repository.
3. Choose a template:
   - **Bug report**
   - **Feature request**
   - **Question**
4. Write a short title that says what happened (example: “Paper dashboard shows blank equity after refresh”).
5. Fill in the template fields. Helpful extras:
   - Steps to reproduce
   - Browser / device
   - Screenshots or a short screen recording
   - Whether you were on paper or live (if you know)
6. Click **Submit new issue**.

That creates a public ticket we can discuss and track.

### Tips for a great report

- One problem per issue when possible.
- Actual vs expected behavior in plain language.
- If it happens only sometimes, say so.
- Do **not** paste passwords, API keys, account numbers, or full brokerage statements. Redact sensitive data.

## How to track issues

### Browse everything

- **All issues:** [https://github.com/guymaim/robo-trader/issues](https://github.com/guymaim/robo-trader/issues)
- Filter with the search bar (examples: `is:open label:bug`, `is:closed`).

### Follow one issue

1. Open the issue page.
2. Read the description, labels, and comments.
3. Click **Subscribe** (or Watch) to get notified of comments and status changes.
4. Reply in a comment if we ask for more detail — that unblocks fixes.

### Understand status

| Signal | Meaning |
|---|---|
| **Open** | Still active — not finished |
| **Closed** | Done, duplicate, or won’t fix — read the last comments |
| Labels like `triage` | Newly filed; we have not sorted it yet |
| Labels like `in progress` | Work has started |
| Labels like `blocked` | Waiting on information or an external dependency |
| Linked pull requests / commits | Engineering work in private repos may appear as references when relevant |

### Releases

When user-facing changes ship, they are summarized in [RELEASE_NOTES.md](../RELEASE_NOTES.md). If your issue is fixed in a release, we often mention the issue number there or in a closing comment.

---

## What not to put in issues

- Secrets (API keys, passwords, session cookies)
- Full account identifiers or tax IDs
- Requests that ask us to publish private implementation or hosting details

Product feedback and clear bug reports are always appropriate.
